## 11. Architecture Decisions

### AD-01: Two Planes, One Authority (双平面法定职责)
- **Decision**: Pi 掌控认知、规划与质询；Invar Core 掌控权威状态、真实执行、证据链与门禁。
- **Why**: 彻底杜绝大模型在会话中自行发明第二套状态机或口头宣称漏洞。
- **Do not revert unless**: 出现新的形式化验证理论证明模型具备无偏且完全确定性的自我状态约束。

### AD-02: Root Cause Fingerprinting (根因指纹排他性)
- **Decision**: `CandidateFingerprint` 仅依据 `attack_class`, `boundary`, `sink_component`, `missing_control` 计算散列。
- **Why**: 行号会随代码迭代变动，Agent ID 会随调度变动。基于行号打指纹会导致相同根因在多端点、多轮次被无限重复上报。
- **Do not revert unless**: 业务架构要求同一服务内的同一缺失防御必须按路由物理行号强行立项。

### AD-03: No Self-Verification as Final Proof (禁止自我复核)
- **Decision**: `IndependentVerifier` 强制检查 `originator_id != verifier_id`，发现漏洞的 Hunter 无权签署复核结果。
- **Why**: 认知偏见（Cognitive Bias）会导致同一个模型上下文在复核自己发现的漏洞时盲目寻找支撑证据，忽视反驳证据（如 WAF 或上层拦截）。

### AD-04: Strict Schema & Zero Severity on needs_validation
- **Decision**: 处于 `needs_validation` 的记录在 Schema 中强制校验 `severity is None`。
- **Why**: 存疑不是漏洞。给存疑记录标注“高危”仅为了报告醒目，属于严重的信息欺诈，会引发海量无效排查。

### AD-05: Reporting as Pure Projection (战报纯投影化)
- **Decision**: 报告是底层事实的只读投影。任何未在 `findings.json` 或 `CoverageLedger` 中存在的事实，绝不可在 Markdown 中出现。

## 15. Failure / Pitfall Registry

### Pitfall-01: Python 逻辑短路求值导致空列表回退 (Short-circuit Defaulting)
- **Problem**: 测试传入 `evidence_refs=[]` 试图断言 Schema 拦截“无证据实锤”，测试却失败报告没有抛出异常。
- **Symptom**: `AssertionError: FindingSchemaError not raised`
- **Root Cause**: 代码使用 `eff_evidence = evidence_refs or candidate.evidence_refs`。在 Python 中 `[]` 判定为 `False`，短路回退为 candidate 的非空证据。
- **Correct Fix**: 采用显式空值守卫：`candidate.evidence_refs if evidence_refs is None else evidence_refs`。
- **Prevention**: 涉及容器列表参数的默认回退，严禁直接使用 `a or b`，必须显式检查 `is None`。

### Pitfall-02: 模糊子系统匹配导致审查端点超范围拉取 (Over-broad Path Matching)
- **Problem**: 单个覆盖单元审查用例中，期望审查 1 个路径，实际却审查了 2 个。
- **Symptom**: `AssertionError: Lists differ: ['/api/orders/batch', '/api/orders/list'] != ['/api/orders/list']`
- **Root Cause**: `Hunter.hunt()` 筛选条件写为 `if ep.path in unit.starting_paths or unit.subsystem in ep.path`。当指定了起始路径时，后面的 `subsystem` 将同业务下的其他高危接口一并带入。
- **Correct Fix**: 确立优先级规则：当 `unit.starting_paths` 非空时，严格按指定路径收敛；仅当其为空时才回退至 `subsystem` 兜底。

### Pitfall-03: task_id 与 endpoint_id 概念边界混淆
- **Problem**: 向后兼容模式下，将任务执行 ID（如 `LEGACY-001`）直接赋值给端点身份 `endpoint.endpoint_id`。
- **Symptom**: `AssertionError: 'LEGACY-001' != 'GET:/api/legacy'`
- **Root Cause**: 混淆了 Task 执行实例与物理 API 端点契约。
- **Correct Fix**: 确立优先级：显式 `endpoint_id` > 动词与路由投影 (`f"{method}:{path}"`) > 冒号格式 `case_id` / `task_id`。
