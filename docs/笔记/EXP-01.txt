## 黄金标准对齐版

## 0. 实验性质

本阶段不是架构实现。

本阶段只回答一个问题：

> **当前 Invar 已有代码是否已经具备“对象引用识别”的足够能力；如果没有，外部 Claude-Red / A.I.G 的相关机制是否提供了一个经过证据支持的、可迁移的共性抽象。**

因此：

```text

```

# 1. FACT / DERIVED / ASSUMPTION / EXPERIMENT 分层

### FACT

Claude-Red 当前 IDOR Skill：

```text
建立测试账户
→ 建立正常访问基线
→ 找出请求中的对象标识
→ 跨主体重放
→ 修改对象引用
```

并明确指出对象引用可能出现在 URL、Body、Cookie、Header、JWT Claim、嵌套 JSON、数组等位置。

### FACT

A.I.G 当前授权 Skill：

```text
跨用户 / 跨租户
权限提升
认证绕过 / 角色混淆
```

并要求只有目标真正具有 users、roles、privileged operations 时才使用该 Skill。

### FACT

A.I.G 新版蓝军 Skill 要求：

```text
能力建模
→ 信任边界
→ 风险假设
→ 最小无害测试
→ 真实证据
```

并要求测试过程中的下一轮只改变一个变量。

### FACT

当前 Invar 已存在：

```text
ResearchTask
ResearchCase
ProbeAttempt
EvidenceRecord
ThreatModel
ResearchScope
```

且 `ResearchTask` 目前承担执行任务身份与 endpoint / coverage / hypothesis 等关联，不应未经证据直接扩展成新的安全语义容器。

### DERIVED

当前真正需要验证的是：

> **现有 Invar 的候选识别层，是否已经能够从 EndpointIR / 请求结构中提取“对象引用语义”；还是目前仍只是关键词启发式。**

### ASSUMPTION

暂时不能假设：

```text
当前系统只有关键词启发式
```

必须从真实源码确认。

### EXPERIMENT

因此 EXP-01 的第一阶段不是构造 12 个假样本。

而是：

> **只读取现有 Invar 中与“授权候选 / 参数提取 / EndpointIR / IDOR 分类”直接相关的源码和测试，确认当前真实能力。**

# 4. Object Reference 暂时不定义为类型

这是本阶段非常重要的约束。

现在禁止做：

```text
class ObjectReference
struct ObjectReference
enum ObjectReference
```

也禁止：

```text
ResearchTask.object_reference
EndpointIR.object_reference
Candidate.object_reference
```

原因：

> **我们现在还不知道“对象引用”是不是当前系统真实缺失的契约。**

只有源码 + 测试证明：

```text
当前职责边界无法表达
+
外部机制确实提供稳定增益
```

以后才进入契约设计。

---

# 5. EXP-01 的真正实验变量

第一阶段只有一个变量：

```text
“当前 Invar 已有实现”
```

暂时不存在：

```text
Method A vs Method B
```

因为 Method B 还没有被实现，也没有经过当前仓库契约约束。

因此当前正确流程是：

```text
真实源码
↓
真实测试
↓
确定当前机制
↓
与外部机制对照
↓
判断是否存在真实缺口
```

而不是：

```text
先发明 Semantic Classifier
↓
再证明它比旧系统好
```

后者违反“有依据才实现”。

```text

```

因此只能把它作为**授权语义建模参考**，不能伪装成 HTTP IDOR 实现。

# 8. 判断规则

审计结束后，只允许出现三种结果。

## RESULT-A：已有能力

如果源码证明：

```text
对象引用
+
主体
+
授权关系
```

已经能够通过现有类型完整表达：

则：

```text
INVAR-EXISTS
```

不新增契约。

---

## RESULT-B：只有候选启发式

如果源码证明：

```text
只知道参数可能是 ID
```

却不能表达：

```text
对象是什么
对象属于谁
当前主体是谁
对象引用为什么成立
```

则：

```text
INVAR-PARTIAL
```

此时才允许继续进入第二阶段实验。

---

## RESULT-C：真实缺失

只有源码 + 测试共同证明：

```text
现有机制无法表达
+
外部机制能够提供稳定、可验证的新信息
```

才标记：

```text
INVAR-MISSING
```

并进入下一轮最小实验设计。
