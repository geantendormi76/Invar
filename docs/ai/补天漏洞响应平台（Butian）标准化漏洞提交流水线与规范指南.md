# 补天漏洞响应平台（Butian）标准化漏洞提交流水线与规范指南

> **版本**：v2.0（基于平台 2025/2026 最新审核规范制定）  
> **适用对象**：自动化安全审计智能体（Agent）及白帽子研究员  
> **核心目标**：实现 100% 契合平台审核规范的漏洞报告生成，杜绝格式驳回与权重误填，确保单次提交直接过审（保底 1~4 库币）。

---

## 1. 核心审核机制与红线约束

1. **强证据链要求**：报告必须同时包含**漏洞利用全过程、完整请求/响应数据包、PoC/复现步骤及厂商归属证明**，缺失任一要素直接驳回。
2. **简要描述红线**：**严禁**在「简要描述」字段中填写任何具体的漏洞 URL、参数、Payload 或敏感信息，违者直接打回。
3. **爱站权重一票否决制**：公益/未注册厂商的「漏洞权重」必须严格依据爱站网查询结果填报。**权重为 0 的厂商必须选 0**，选错或虚标直接驳回。
4. **匿名机制说明**：勾选「匿名提交」后，平台将对公众隐藏白帽子真实昵称，统一对外展示为代号**“带头大哥”**。

## 2. 漏洞提交表单全字段 Schema 与填报契约

| 字段名称 | 界面类型 | 是否必填 | 规范填报要求与约束 |
|---|---|---|---|
| **厂商名称** | 下拉/搜索 | **是** | 必须填写标准全称。例：`全讯汇聚网络科技(北京)有限公司`。专属 SRC 项目需严格匹配企业全称。 |
| **厂商资产范围** | 系统展示 | 只读 | 系统根据厂商信息自动展示（如：`无限制` 或具体业务系统范围）。 |
| **域名或IP** | 单行文本 | **是** | **必须提供标准主域名**（不带协议头和路径）。例：`www.ikuai8.com` 或 `ikuai8.com`，严禁直接填写长 URL。 |
| **漏洞类别** | 下拉选择 | **是** | 选项：`Web漏洞` / `IoT漏洞` / `工控漏洞` / `操作系统及通用软件漏洞`。<br>（注：专属 SRC 统一选择 `Web漏洞`）。 |
| **漏洞标题** | 单行文本 | **是** | **固定命名格式**：`[单位/企业全称/特定系统] + [漏洞类型]`。<br>合格例：`全讯汇聚网络科技(北京)有限公司某系统存在敏感信息泄露漏洞`<br>不合格例：`发现一个越权`、`SQL注入漏洞`。 |
| **漏洞URL** | 单行文本 | **是** | 必须以 `http://` 或 `https://` 开头。<br>① 若为 **GET 请求**，必须提交带测试参数的完整 URL；<br>② 若为 **POST 请求**，此处填写基地址，数据包在下方详情展示。支持 `+添加URL`。 |
| **漏洞类型** | 级联下拉 | **是** | 一级分类：`事件型`（常规业务系统漏洞） / `通用型`（CMS、开源组件框架通用漏洞）。<br>二级分类选择具体类型：`敏感信息泄露`、`未授权访问`、`SQL注入`、`弱口令`、`权限绕过` 等。 |
| **漏洞等级** | 下拉选择 | **是** | 选项：`低危` / `中危` / `高危` / `严重`。<br>（注：信息泄露、Swagger 未授权、配置不当等一般选 `低危`）。 |
| **漏洞权重** | 下拉选择 | **是** | **核心计分字段**。依据爱站网（aizhan.com）针对**主域名**的权重查询结果：<br>① `百度权重 >= 1` 或 `移动权重 >= 1` 或 `谷歌权重 >= 3` $\to$ 选择 `权重 >= 1`；<br>② 其余情况一律严格选择 `权重 = 0`。 |
| **参与活动/任务** | 下拉选择 | 否 | 若个人中心已领取对应专属悬赏任务或活动，必须手动下拉勾选；未选择则默认不享受额外活动奖金。 |
| **简要描述** | 多行文本 | **是** | **仅简述漏洞业务影响与危害范畴**。<br>⚠️ **致命红线**：禁止在此处出现具体 URL、IP 或 Payload！ |
| **详细细节** | 富文本编辑 | **是** | 核心报告主体。必须包含：① 复现过程与请求/响应包；② 归属证明；③ 首页截图；④ 危害验证截图。 |
| **附件** | 文件上传 | 否 | 仅支持 `zip` / `rar` 压缩包，大小不超过 `50MB`。用于存放复现脚本/固件/长操作录像。如能在文本中说明的内容**严禁**偷懒塞入附件。 |
| **修复方案** | 多行文本 | **是** | 给出具体防御建议。例：`建议在服务端配置中关闭对应调试端点，对敏感字段进行掩码脱敏处理。` |
| **行业/地区** | 级联下拉 | 否 | 如已知可填，通常可保持默认或由平台根据企业工商信息自动关联。 |
| **匿名提交** | 复选框 | 选填 | 勾选 `☑ 匿名提交（平台不会公开白帽子细节，显示为“带头大哥”）`。 |

## 3. 四大必备证明材料标准（审核通过判定基准）

在「详细细节」字段中，必须提供以下 4 项明确的证明截图（富文本中插入图片或以清晰图文展示）：

```text
[必备证据链]
  ├── 1. 漏洞目标地址截图 (包含浏览器地址栏完整 URL)
  ├── 2. 厂商资产归属证明 (百度检索/工信部备案/软著证明/页面版权)
  ├── 3. 目标系统首页截图 (带浏览器地址栏，用于存证目标状态)
  └── 4. 漏洞危害实证截图 (PoC 执行结果 / 泄露字段高亮 / 越权数据对账)
```

1. **漏洞网址截图（含完整浏览器地址栏）**：
   * 截图必须露出顶部的完整 URL 地址（包含协议、端口及测试路径），严禁裁剪只剩页面正文。
2. **厂商归属证明截图**：
   * **证明该资产确实归属于被报厂商**。常见证明方式：
     * 百度搜索目标域名/系统名称，显示对应企业官网结果；
     * 目标页面底部的 `ICP备案号` 或 `© 某某科技有限公司 版权所有`；
     * 系统登录界面/后台带有厂商名称或 Logo 标识。
3. **首页截图（含地址栏）**：
   * 访问该子域/系统的根路径（首页），截取带有地址栏的完整浏览器界面。
4. **漏洞证明截图（危害落地证据）**：
   * 严禁只发一个裸请求包，必须展示明确的危害事实：
     * 信息泄露类：截取返回包中包含的明文密码、未脱敏手机号、API Secret、内网 IP 等；
     * 弱口令/未授权类：截取成功进入后台、获取敏感菜单权限的界面；
     * 命令/注入类：截取 `whoami`、回显敏感系统信息的界面。

#### 步骤一：定位存在问题的端点
访问目标系统端点：
`GET/POST https://subdomain.target.com/api/example/path`

#### 步骤二：构造验证请求包
完整 HTTP 请求如下：
```http
POST /api/v1/example/endpoint HTTP/1.1

服务端直接返回包含敏感字段的响应，无需鉴权拦截：

  "code": 200,

  }
}
```

## 5. 常见驳回陷阱与避坑准则

1. **陷阱一：在「简要描述」中写了具体 URL**  
   * **后果**：直接以“格式不合规”秒驳回。  
   * **准则**：简要描述只允许写“本漏洞属于敏感接口信息泄露，攻击者可通过该缺陷直接获取敏感凭证”，不可写任何路径。
2. **陷阱二：权重选错（权重 0 误填为权重 1）**  
   * **后果**：平台一律直接驳回。  
   * **准则**：只要爱站未收录或权重查询显示 0，必须果断勾选 `权重=0`，切勿侥幸多选。
3. **陷阱三：拿 4003 / 401 报错充当未授权漏洞**  
   * **后果**：厂商以“未产生危害/拦截生效”为由忽略，扣除提交信誉分。  
   * **准则**：只要返回包带 `forbidden` 或明确的权限阻断提示，绝不能作为未授权提交；必须证明拿到实质性数据。
4. **陷阱四：缺失地址栏或无厂商归属证据**  
   * **后果**：因“无法核实资产归属”驳回。  
   * **准则**：截图必须全屏或保留浏览器地址栏；若子域名不明显，必须附上备案查询或百度搜索关联截图。
